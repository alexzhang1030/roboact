# i18n

**Current conclusion.** Two catalogs, `web/i18n/en.js` and `web/i18n/zh-CN.js`, loaded as ES modules (no build). Same key set. `t()` uses the active locale, then English, then `''` — never the key name.

## First load

`detectBrowserLang` in `web/js/prefs.js` is the **one** function for first-load language. Read `navigator.languages`; first entry starting with `zh` → `zh-CN`, else English (also the fallback when nothing can be read). Flip `FOLLOW_BROWSER_LANG` to `false` for always-English first load; keep the same constant in the `web/index.html` head script (that script only exists so the first paint is already the right language).

Manual pick persists as `roboact.lang` = `en` | `zh-CN`. Follow-browser deletes the key. A second tab follows via `storage`.

## What is translated

UI chrome only. Units are never translated. User-written node names, notes, and values are never translated. Adapter action titles: `labels[locale]` then `labels.en` then `name` then `id` — never blank.

Storage, SSE, HTTP, and exported flows carry **codes** (`paused`, `operator_lost`, `timeout`, `precondition_failed`, …). The UI maps code → text. Do not persist Chinese or English status words.

## Why

After a crash the executor must compare codes, not sentences. Switching language on an old run must relabel the same code. English is the fallback so a missing Chinese key never shows the key name.

## Rejected

- Hard-coded CJK in `web/` outside the catalogs.
- r-token / token-gate catalog keys (auth deferred; see [auth-and-network.md](auth-and-network.md)).
- Translating units or operator-typed names.

## Tests

`tests/test_i18n.py` fails if catalog keys differ or if `web/` (except the two catalogs and vendor) contains CJK. Playwright default locale is en-US. Browser tests that assert words must use English, or set `locale="zh-CN"` on the context.
