# i18n

Catalogs: `web/i18n/en.js`, `web/i18n/zh-CN.js`. First `zh*` in `navigator.languages` → Chinese, else English. Wire format is codes. Missing zh key falls back to English.

Python never uses `zh(...)` for a default flow name, default param value, or adapter name. Those stored/default values are English (`en(...)`). Per-locale `labels={"en":..., "zh-CN":...}` dicts stay bilingual. `append_note` still accepts the zh-CN catalog value of `parse.note_content` as a last-resort arg key (`zh("parse.note_content")`); it does not write that string.
